This directory is not a copy of that archive. The archive's PlayerbotV2 module
does not compile against forever 550546617a. CreationPolicy.h records the
level and population rules that replace the archive's GiveLevel(owner level)
and level-10 world buckets. ClassicArmor.h, ClassicSpellValue.h, the
handcrafted road graph, and handcrafted_road SQL are not imported.

Public compile of the archive, g++ 13.3.0, against this tree's headers:

  BotCharacterFactory.cpp includes Session/BotSession.h
    error: BotSession destructor marked override, but WorldSession's destructor was not virtual
    error: SendPacket marked override, but WorldSession::SendPacket was not virtual

  Those two declarations are now virtual on this experimental branch, with
  IsBot() defaulting to false. After that, g++ -fsyntax-only:

    BotSession.h included from a probe: exit 0
    BotCharacterFactory.cpp: exit 0 (the creation TU parses)
    BotSession.cpp: fatal error: LoginQueryHolder.h: No such file or directory
    BotPopulationManager.cpp: ‘class Group’ has no member named ‘ReorderMembers’
    PlayerbotV2.cpp: fatal error: BotGroupRules.h: No such file or directory

  LoginQueryHolder now has a public header. Initialize() stays in
  CharacterHandler.cpp. BotSession drops packets, can submit that holder,
  and does not call InitializeSession or look up a battlenet account.

  CharacterFactory.cpp calls Player::Create and SaveToDB for a new guid on
  a caller-supplied player-security pool account. Alliance and horde ids
  must differ. The saved level is 1, or the character is not saved.
  GiveLevel is not called. The character insert and the
  playerbot_v2_character marker share one transaction. A second create of
  the same owned level-1 name returns the existing guid. Startup does not
  call the factory. .playerbot create, login, and logout return before a
  session or a query while Enable is 0 or the kill switch is 1. Login and
  logout touch only a level-1 marker row this module opened. Closing the
  gate kicks those sessions and no others.

  Owned bots accept a same-faction non-bot group invite. One core
  PathGenerator step or one melee Attack runs per tick. A path is followed
  only when it is PATHFIND_NORMAL or PATHFIND_INCOMPLETE, is not a shortcut
  or far from the mesh, and the next point is within 12 yards horizontally
  and 4 yards vertically. Anything else leaves the bot where it stands.
  There is no teleport, capital move, or level boost. Starter areas are not
  treated as permanently unpathable; a tile is used when PathGenerator
  accepts it. This cloud build has no 70862 mmaps, so no walk was observed.

  Archive BotAI, the handcrafted road graph, ClassicArmor, and
  ClassicSpellValue are not linked. Quest progress is not implemented.

  Group::IsRaidForQuests keeps isRaidGroup() when no member session is a
  bot. Tap sharing and round-robin loot use BotGroupRules and match the
  previous walk in that case. ReorderMembers and BotPopulationManager are
  not imported.
